# Browser rendering approach

Research and decision: October 7, 2026. Priorities are interactive speed and visual fidelity together, with an editable local house rather than a fixed showroom.

## Decision

Use the existing Three.js WebGL2 physically based raster renderer, and optimize when and how much it renders. Replace progressive path tracing in the interactive quality selector with an immediate Presentation view. Keep the material maps, detailed furniture, environment lighting, and settled contact shading developed in the fidelity pass.

This is a workload-specific choice. We have not established that WebGL is universally faster than WebGPU or benchmarked every browser engine. Backend names alone do not establish performance.

## Implementation and verification

The implementation uses demand frames with explicit camera invalidation, cached shadows refreshed after visual edits, contact shading restored after movement settles, per-material furniture batches within each saved piece, cached CPU material pixels, and bounded display/AO resolution. Presentation retains the serialized `refined` value for compatibility and renders immediately without sample accumulation. The path-tracer dependencies and worker pipeline have been removed.

[Measured results and limitations](render-performance.md) record the matching Intel browser comparison. Observed Live orbit draw-frame intervals improved from 49.9/66.7 ms median/p95 to 16.7/16.7 ms; settled Live and Presentation submitted zero idle draws. The settled material/furniture appearance is preserved, including a byte-identical exterior capture. Lighting remains an approximation rather than converged global illumination.

Measurements use the same synthetic house and browser configuration on an isolated server. Report actual browser GPU, active render intervals and draw calls, idle draw activity, image provenance, and capture latency. Browser animation callbacks alone are not proof that the house rendered a frame. Software GPU results and hardware results must remain separately labeled.

Both Astra source and image reviews passed. The final clean lifecycle run verified orbit and held-key walkthrough motion, selection and labels, visual edits, quality modes, resizing, context recovery, and capture of edited geometry without browser warnings/errors. The full 204-test suite and production build passed. Real project files remained byte-identical.
